# 真实分子三加速器后端接入设计

## 目标

保持现有前端文件和请求协议不变，让 `/api/v1/pipeline` 产生的真实候选
SMILES 经后端编码后，通过开发板现有 `192.168.1.10:5001` TCP 服务执行
Tanimoto、GNN 和 ADMET 三种硬件计算，并把可审计结果附加到候选分子。

## 边界

- 只修改 Python 后端；不修改 Vue 前端、Vivado 工程、RTL 或板端固件。
- 复用现有 16 字节小端 TCP 帧和 DMA 批处理协议，不新增网络协议。
- FPGA 离线、超时或分子超出 50 原子限制时保留原推荐结果，并明确记录回退原因。
- 当前 GNN/ADMET 为确定性验收权重，输出只作为硬件链路证据，不参与科学排名。
- Tanimoto 是确定的指纹相似度，可作为推荐辅助字段；本阶段不改变现有总分，避免
  因默认参考分子选择而改变前端行为。

## 数据流

1. Generator 生成最多 5 个真实候选 SMILES。
2. 后端以第一个可编码候选作为本批次 Tanimoto 参考分子。
3. RDKit 将每个候选编码为：
   - 1024 位 Morgan radius-2 指纹，按 32 个 little-endian `u32` 打包；
   - 50x50 含自环邻接矩阵，按 row-major、LSB-first 打包为 79 个 `u32`；
   - 50x64 原子特征，signed Q8.8，每个 `u32` 低 16 位在前，共 1600 words；
   - 20 个标准化 RDKit 描述符，signed Q8.8，各占一个 `u32` 的低 16 位。
4. 后端分别发送三次批请求：Tanimoto、GNN、ADMET。
5. 将结果按候选 ID 合并到 `fpga_evaluation`，包含原始定点值、解码值、
   trace ID、批大小、延迟、执行状态和权重用途说明。
6. Reviewer 深拷贝候选时自动保留该字段，原有 API 响应结构保持向后兼容。

## 错误处理

- 单个无效/超限分子标记 `not_encodable`，不阻止其他分子执行。
- 网络或协议失败时本批次标记 `fallback`，不伪造硬件输出。
- 响应 magic、version、task、trace、batch、长度均需校验。
- 仅当三次响应全部成功时，批次状态为 `hardware_complete`。

## 验证

- 单元测试验证分子特征尺寸、位序、Q8.8 饱和和协议帧校验。
- 模拟 TCP 响应验证结果映射和错误回退。
- Orchestrator 测试验证真实候选会调用硬件评估且保留原推荐字段。
- 上板测试用多个真实 SMILES 执行三任务，并用 CPU Tanimoto 交叉校验。
- 前后两次对 77 个前端源文件做 SHA-256 清单比较，必须完全一致。
